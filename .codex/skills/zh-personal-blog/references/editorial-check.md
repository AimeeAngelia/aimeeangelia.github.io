# 个人博客审校

按问题影响排序审校，不把它当词语替换器。

## 1. 事实锁

逐项核对姓名、产品、版本、路径、命令、数字、日期、价格、链接、引用、否定词和范围词。删除任何无法追溯到材料的新增经历、效果、因果或动机。

## 2. 是否仍像作者

- 有没有把个人判断改成中性百科？
- 有没有把原本自然的补充、犹豫或不对称段落全部修平？
- 有没有为了“活人感”加入作者平时不用的梗、口头禅或情绪？
- 技术文章是否仍然优先准确，兴趣文章是否保留了轻重不均的真实关注点？

## 3. 成簇出现的模板痕迹

单独出现一次不必修改；在短距离内反复出现时再处理：

- “真正……的不是……而是……”“不只是……更是……”等舞台式对比；
- “首先、其次、最后、综上所述”组成的讲义路线；
- 每节都先宣布价值，再解释内容，最后补一句金句；
- “值得注意的是、毋庸置疑、不可忽视、在当今……”等无信息暖场；
- 连续三项排比、每段同样长度、标题层级过密；
- “开启新篇章、未来可期、让我们拭目以待”等空结尾；
- 把具体动作替换为“赋能、助力、推动、打造闭环”等抽象动作；
- “当然可以、希望对你有帮助”等聊天助手残留。

处理方式通常是删掉舞台句，直接留下事实或判断。不要寻找另一句同样套路的替代表达。

## 4. 是否过度完整

- 文章是否为了显得专业，补了用户没有经历的背景、比较或建议？
- 一个小问题是否被扩写成“完整指南”？
- 开头是否在正文前重复摘要，结尾是否又重复一次正文？
- 每个列表项是否被强行拉成同样篇幅？

能删掉而不损失事实、判断或必要上下文的包装句，应当删除。

## 5. 发布检查

- frontmatter 字段和缩进有效；
- `<!-- more -->` 位于自然的摘要断点；
- 图片、站内路径和外链没有被改坏；
- 代码块语言、命令换行和 Hexo `{% note %}` 标签保持完整；
- 标题和 description 准确描述这一次记录，不使用点击诱导；
- 没有暴露邮箱、手机号、令牌、订阅 ID、内网凭据或其他敏感信息。

默认完成上述检查后只交付终稿，不附带自评、AI 分数或“修改说明”。
